Evidence Pack Quality Audit Report
==================================================

Audit purpose
- Review evidence_pack_assembler_smoke_test_samples.json for six smoke-test questions.
- Assess evidence quality only.
- No answer generation, no LLM call, no Neo4j write, no retrieval re-evaluation.

Input file
- graph_rag_knowledgement/neo4j_load/evidence_traversal/evidence_pack_assembler_smoke_test_samples.json

Overall summary
- Evidence pack generation works for all 6 smoke-test questions.
- Every pack has primary_evidence and citation_candidates.
- Evidence quality is uneven across intents.
- Strongest packs: appointment_requirement, applicability_check, penalty_lookup as penalty-only source evidence.
- Needs improvement before answer generation: education_time_lookup, inspection_requirement, obligation_check for the risk-assessment query.
- Main recurring issue: beta keyword retrieval can return legally valid evidence that is not the best answer evidence for the user's exact question.

Cross-pack issues
1. Encoding/display issue in PowerShell output
- Some PowerShell output showed mojibake, but the JSON file itself is UTF-8 and Python reading displayed Korean correctly.
- This is not an evidence quality issue.

2. Query-term alignment
- The assembler now decomposes Korean query text into terms, but quality audit shows some intents need domain-specific critical term checks.
- Add per-intent required term or concept checks before allowing OK status.

3. Warning calibration
- Warnings are useful but need better pack-level vs item-level distinction.
- education_time_lookup should not mark the whole pack as threshold-missing if at least one strong threshold/annex evidence exists.
- obligation_check should warn when retrieved rules do not contain the core domain term.

4. Citation quality
- Citation candidates exist for every pack.
- For table/list questions, citation should prefer Annex/LogicalRow/LogicalCell over broad article citations.

Final recommendations
- Do not proceed directly to answer generation for all intents.
- Proceed with answer-generation prototype only for READY/READY_WITH_WARNINGS packs while preserving warnings.
- Before answer generation, improve:
  1. risk-assessment query retrieval alignment,
  2. education-time Annex table expansion,
  3. inspection/list equipment-specific ranking,
  4. warning calibration for weak evidence alignment.
